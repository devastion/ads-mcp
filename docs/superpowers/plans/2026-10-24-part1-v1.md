# Part 1 v1 Search API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `GET /api/v1/ads` (keyword search, four filters, two sorts, signed keyset cursors, one error envelope, a generated and drift-checked OpenAPI spec, Bearer auth) without any change that v0 callers can observe.

**Architecture:** v1 has its own controller, FormRequest, resource, error renderer and auth middleware. Only the filter predicates are shared with v0: they move into `App\Actions\AdSearchPredicates` (a behaviour-preserving extraction), which both `SearchAds` (v0) and the v1 search Action call. v1 owns its ordering, its cursor and its validation. Error codes live in one backed enum, `App\Enums\ApiErrorCode`, so the MCP server can reuse them.

**Tech Stack:** PHP 8.5.12, Laravel 13.38, Pest 5.3.3, PHPUnit 13.4.3, Postgres 18.6 (app and tests), Larastan 3.13.2 at level 7, Pint, `dedoc/scramble` 0.13.50 (approved by the user).

**Spec:** `docs/superpowers/specs/2026-10-24-part1-v1-design.md` (approved). It implements `ASSESSMENT.md` Part 1. Executors read the spec, the assessment's Part 1 section, and the v0 guard (`/Users/devastion/Projects/ads/.agents/skills/v0-contract-guard/SKILL.md` and its `references/v0-contract.md`; this path is in the main checkout because `.agents/` is gitignored).

## Global Constraints

- `per_page`: default `20`, allowed `1` to `100`, out of range is rejected, never clamped (design decision; v0 still clamps).
- Sort `newest` orders by `start_date` descending. Sort `impressions` orders `impression_rank` ascending, nulls last, then `id` ascending.
- `niche` takes repeated slugs only: `niche=skincare&niche=haircare`. Comma form is rejected.
- Error envelope on every `api/v1/*` failure: `{"error": {"code", "message", "next_step", "retryable"}}`, plus `details` when there is something to add. `retryable` is true only for `rate_limited` and `internal_error`.
- v0 keeps `{"error":"Invalid request"}` for every `api/v0/*` failure. The v0 contract test (`tests/Feature/Http/Controllers/V0/AdControllerTest.php`) is never edited.
- Every new PHP file comes from `php artisan make:* --no-interaction` (`make:class`, `make:enum`, `make:request`, `make:middleware`, `make:test --pest`, `make:migration`).
- Use Boost `search-docs` before relying on a Laravel or Pest API that this plan does not already quote.
- Code follows `AGENTS.md`: curly braces, constructor promotion, explicit types, PHPDoc array shapes, no inline comments except for complex logic. Subfolders under existing folders are fine (`App\Http\Exceptions\V1`, `App\Http\Controllers\V1`, `App\Http\Requests\V1`, `App\Http\Resources\V1`, `App\Http\Middleware` for auth, `App\DTO\V1`, `App\Actions\V1`). No new top-level folders.
- Tests: Pest `it()`, behaviour-named, factories with explicit values (`brand_id`, `impression_rank`, `start_date`, `status`). Freeze time with `$this->travelTo(...)`. Tests on ties compare sets, not order. Never rely on the factory default `impression_rank = 1` or `brand_id = 1` when more than one ad exists (the table has `unique(brand_id, impression_rank)`).

## Review Focus

These are the inputs most likely to bite a caller. Each is pinned by the test named in the owning task.

1. **Empty or whitespace-only values** (`q=`, `q=%20%20`): the global `TrimStrings` and `ConvertEmptyStringsToNull` middleware turns them into null, which looks absent. v1 must reject them, not ignore them. Pinned in Task 2.
2. **Repeated scalar parameters** (`format=video&format=image`): v0 takes the last value. v1 must reject, not pick one. Pinned in Task 2.
3. **Comma-separated niche** (`niche=skincare,kitchen`): must return `invalid_parameter` with the repeat hint, not an unfiltered 200. Pinned in Task 6.
4. **Impossible calendar date** (`started_after=2026-02-30`): PHP's date parser rolls it over, so it must be rejected explicitly. Pinned in Task 9.
5. **Tampered, truncated or cross-query cursor**: must return `invalid_cursor` or `cursor_mismatch`, never a page. Pinned in Task 11.
6. **Route-level errors on v1** (`POST /api/v1/ads`, unknown `/api/v1/*` path, a thrown exception): must use the envelope, with `Allow` kept on 405 and no internal detail on 500. Pinned in Task 1.

### Tasks 5 to 9: one filter per task

Each filter task follows the same steps. Run them **one at a time, in order**. They all edit `SearchAdsRequest::rules()`, `AdSearchQuery` and the shared predicates, so they are not safe to run in parallel even in separate worktrees. Dispatching them in parallel would only cause merge conflicts. The per-filter tests are what the user asked to be independent, and they are independent in behaviour, not in files.

Each task's test has the same shape: seed ads that differ **only** in the filter under test, call the endpoint with and without the filter, and assert the exact matching subset (by id set). If the filter were silently ignored, the set would be wrong, so the test fails. Each task also asserts the filter is echoed in `applied_filters`.

### Task 11: Cursor codec, binding and error codes

**Files:** Create `app/Actions/V1/CursorCodec.php`, one Action with `encode` and `decode`. Modify `AdController` (set `next_cursor`). Test: `tests/Unit/Actions/V1/CursorCodecTest.php` and `tests/Feature/Http/Controllers/V1/CursorValidationTest.php`.

**Interfaces:**
- Produces: `encode(array $payload): string` gives `base64url(json) . '.' . base64url(hmac)`, where `hmac = hash_hmac('sha256', <json bytes>, <key>)` and `<key>` is derived from `config('app.key')` with a fixed purpose string (for example `hash_hkdf('sha256', config('app.key'), 0, 'v1-cursor')`). No expiry.
- Produces: `decode(string $cursor): array` throws `ApiErrorException` with `InvalidCursor` for a malformed value, bad base64, bad JSON, or an HMAC mismatch. Verify the HMAC with `hash_equals`.
- Payload keys (from the design): `v` (1), `h` (hash of the normalised filters and sort, built by `AdSearchQuery::fingerprint()` with `sha256` over the JSON of `appliedFilters()`, which excludes `per_page` and `cursor`), `c` (snapshot cutoff), `k` (last sort key), `i` (last id).
- Binding: a decoded cursor whose `h` does not equal the current query's fingerprint throws `ApiErrorException` with `CursorMismatch`.

      expect($codec->decode($codec->encode($payload)))->toBe($payload);
  });

  it('rejects a cursor whose payload was changed', function () {
      $codec = app(CursorCodec::class);
      [, $sig] = explode('.', $codec->encode(['v' => 1, 'h' => 'abc', 'c' => 1, 'k' => 'x', 'i' => 1]));
      $tamperedBody = rtrim(strtr(base64_encode('{"v":1,"h":"abc","c":999,"k":"x","i":1}'), '+/', '-_'), '=');

  });
